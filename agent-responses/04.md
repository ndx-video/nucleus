Phase 2.0 — True Reviewer Isolation

How /review worked before
Same session: applyRole(reviewer) → build bundle → pi.sendUserMessage(bundle).  
Implementer history could still sit in the branch (hybrid isolation).

Isolation path chosen

Pi supports ctx.newSession({ parentSession, withSession }), which creates a blank session (no conversation copy). That is the preferred path.

/review
  → gate (verified attestations only)
  → phase → Reviewing, role → reviewer (on disk)
  → build Review Bundle (+ independent re-exec)
  → write .nucleus/review-bundle.md + review-session.json
  → ctx.newSession({
       withSession: inject ONLY kickoff (isolation header + bundle)
     })
  → new extension instance session_start:
       apply Reviewer model + tools before kickoff

Fallback: if newSession is missing, cancelled, or throws → same-session inject, recorded as same_session_fallback.  
Force hybrid: /review same

What the Reviewer sees
Only the kickoff message:
1. Spec  
2. Diff  
3. Integrity-verified attestation(s)  
4. Independent re-execution (MATCH / MISMATCH)  

No Implementer chain-of-thought. HMAC + re-exec layers unchanged.
